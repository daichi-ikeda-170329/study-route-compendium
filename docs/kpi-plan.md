# KPI と改善の判断

**基準値は空欄のままにしてある。**この作業では Search Console・GA4・AdSense・
アフィリエイトの管理画面にアクセスできなかったため、数値を埋めていない。
**推測で埋めない。**取得したら運営者が埋める。

取得の手順は「取得のしかた」に書いた。個人が特定できる値は書かない
（志望校・学部・偏差値・個別の閲覧履歴は、そもそも計測していない）。

## 見かた

上ほど優先する。**上の指標を下の指標のために犠牲にしない。**

| 優先 | KPI | 判定 |
|---:|---|---|
| 公益 | ルート採用教材の書誌確認率 | 増える。**未確認を隠して上げない**（`docs/data-quality.md` の件数で見る） |
| 公益 | 誤情報の報告から訂正までの日数 | 短くなる |
| 公益 | 主要導線の内部リンク切れ | 0（`npm run check:site` で常時 0） |
| UX | 診断完了率・保存利用率・再訪 | 改善する。センシティブな値は送らないまま |
| SEO | 非ブランド検索の表示回数・クリック、index の有効率 | 28 日対 28 日で傾向を見る |
| SEO | 主要ランディングページの CTR | title を変えた前後を同じ期間で比べる |
| 収益 | 書籍詳細からのアフィリエイトクリック率 | 公益のガードレールの中で改善する |
| 収益 | 広告 RPM・viewability | CLS・離脱・診断完了率を悪化させない |
| 性能 | Core Web Vitals 合格 URL 比率 | 維持または改善 |

## ガードレール

次のいずれかを悪化させる案は、収益が増えても採用しない。

- 誤クリックを誘う配置（広告をコンテンツや操作ボタンと誤認させる）
- CLS の悪化（広告枠は寸法を先に確保してある）
- 診断の離脱率の悪化
- ページの表示速度の悪化
- 未確認情報を確定情報として見せること

## 判断のしかた

- 季節性が大きい（模試の直後、夏休み、共通テスト前後で動く）。
  **1 週間だけで結論を出さない。**最低 28 日、できれば前年同期と比べる。
- 検索アルゴリズムの更新と自分の変更を混同しない。変更日を記録しておく。
- 施策を同時に複数入れない。入れたら、どれが効いたか判定できない。

## 取得のしかた

いずれも運営者の管理画面が要る（README の「運営者が行う手動設定」）。

1. **Search Console** — 検索パフォーマンス → 期間を 28 日 →「ブランド」を含む
   クエリを除外して非ブランドの数値を出す。ページ単位でも見る
2. **GA4** — レポート → エンゲージメント → イベント。
   イベント名は `docs/analytics-events.md` の表と一致する
3. **AdSense** — レポート → 期間 28 日。RPM と viewability
4. **Amazon アソシエイト / 楽天アフィリエイト** — レポートから注文数
