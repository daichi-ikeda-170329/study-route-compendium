# 文章のスタイルガイド

ルート大全に載せる文章の書き方。**`build/check-site.mjs` がこの文書の機械で見られる部分を検査する。**
条文を変えたら検査も一緒に直す（片方だけ直すと、書いてあるのに守られない規則ができる）。

対象は次のすべて。

| 対象 | 置き場 |
|---|---|
| 参考書の説明文（`desc`）・強み（`pros`）・注意点（`cons`）・向いている人（`bestFor`） | 各科目トップの `BOOKS` |
| ルート・志望レベルの説明 | 各科目トップの `ROUTES` / `TIERS` |
| 解説記事の本文 | `build/content/articles.mjs` |
| 信頼性ページの本文 | `build/content/legal.mjs` |
| 生成テンプレートの地の文 | `build/generate-*.mjs`・`build/lib/*.mjs` |
| 手書き HTML の本文 | `index.html`・`<科目>/index.html`・`404.html` |

---

## 1. 説明文（`desc`）の構成

一覧カードに出る約 100 字。次の 4 つをこの順で書く。④は無くてもよい。

1. **この本の位置づけ** — 役割とレベル。何をする本か
2. **同レベルの他書との違い** — 1 点だけ。ここが無いと「比較できる形で並べる」というサイトの主張と合わない
3. **向く人** — どういう状態の人がこの本を取るか
4. **注意点** — あれば 1 つ

**スペック表に出ている数字を文章で繰り返さない。**難易度・到達目安・想定学習時間・問題数は表にある。文章では、表から読み取れないことだけを書く。

### 例

**Before**（誇張と評価だけで、他書との違いが無い）

> 西きょうじが「読解の思考プロセス」を50題に凝縮した伝説的名著。薄いのに濃く、構文把握が「作業」から「思考」に変わる。早慶・旧帝志望の解釈仕上げの定番であり続ける。

**After**

> 西きょうじによる例題50題の上級解釈書（1993年）。技術100や熟考下と同じ帯だが、構文の型よりも「なぜそう読むか」の思考手順を追わせる構成で、解説は簡潔。基礎解釈（基礎100・入門精講など）を終えた早慶・旧帝志望者の仕上げ向き。演習量は少ないので長文問題集と併用する。

**Before**

> 省略・倒置・比較構文の三大難所を徹底的に掘り下げる最難関解釈書。京大・阪大の重厚な和訳問題への最終兵器として30年君臨する。

**After**

> 省略・倒置・比較の3構文に絞って掘り下げる最難関向け解釈書（研究社）。同帯の解釈教室が網羅型なのに対し、こちらはテーマ特化型で分量が少ない。和訳の配点が大きい京大・阪大志望で、ポレポレ級を終えた人向け。共テ・私大マーク型の受験生には過剰。

## 2. 禁止・要注意語

**機械で検出する。**`build/lib/words.mjs` がこのリストを持ち、`build/check-site.mjs` が使う。
片方だけ増やさないように、`test/style-guide.test.mjs` が下の一覧とあのファイルを突き合わせる
（どちらかを直し忘れるとテストが落ちる）。

### 禁止（誇張・情緒）

伝説、名著、最終兵器、君臨、滅法、豪語、最右翼、国民的、金字塔、決定版、神、最強、圧倒的、無双、必殺、鉄板、至高、究極、王者、絶対

このうち**「神」だけは機械で検出しない**。神戸大・神経・昼神（人名）のように地名・人名・
語の一部として実在し、部分一致では誤検出しか出ないため（`build/lib/words.mjs` の
`BANNED_NOT_CHECKED`）。条文としては禁止のままで、ここは人の目で見る。

### 要注意（根拠が書けるときだけ使う）

- **「定評がある」「支持される」「人気」** — 誰がどう評価したかを書けないなら削る
- **「〜しか鍛えられない」「〜で負けることはない」** — 断定できる根拠がない
- **「事実上の必携」「マスト」** — 必携かどうかは志望校と現在地で変わる

### 例外

- 書名・シリーズ名にこれらの語が入っている本（『合格る計算』など）は当然そのまま書く。検査は書名・正式名称を対象から外す
  - **自分の書名だけでなく、説明文が引用した他書の書名も外す。**1 節が「同レベルの他書との違いを 1 点書く」ことを求めている以上、『大森徹の最強講義126講』のような書名の引用は必ず出る。`check-site.mjs` は収録している全書籍の `name` / `official` を長いものから取り除いてから語を探す
  - 書名リストに載らないシリーズ名（『究極の東大対策』など）は `build/lib/words.mjs` の `BANNED_ALLOW` に、出どころを添えて 1 件ずつ足す。地の文の誇張を通すための逃げ道にしない
- 出版社の惹句を引用するときは、引用であることが分かる形で書く

## 3. 事実と評価を分ける

| 種類 | 例 | 書き方 |
|---|---|---|
| 事実 | 刊行年・問題数・構成・改訂・収録範囲 | そのまま書く。**データに無い事実を文章で足さない** |
| 推定 | 難易度・到達目安・想定学習時間 | 推定であることが分かる形にし、[データの作り方](/methodology/) へ送る |
| 評価 | 向く人・向かない人・他書との違い | 根拠と一緒に書く。根拠が書けないなら書かない |

**説明文を書き換えるとき、新しい事実を足さない。**刊行年・問題数・著者・改訂の有無は `BOOKS` にあるものだけを使う。知らないことを書き足すと誤りが混入する。

---

## 4. 文体

- **説明文（`desc` / `pros` / `cons` / `bestFor`）は常体**（だ・である）。カード上で短く読ませるため
- **本文（記事・信頼性ページ・生成テンプレートの地の文）は敬体**（です・ます）
- 同じテンプレートの中で混ぜない
- 1 文を短く。「〜であり、〜だが、〜ので、〜である」とつながる文は切る

## 5. 表記

| 項目 | 決め | 備考 |
|---|---|---|
| サイトの呼び方 | **「本サイト」「ルート大全」** | 「本アプリ」は使わない（Web サイトなので事実に反する） |
| 括弧 | 日本語の文中は**全角**（）、書名・型番の中は原文どおり | 説明文は従来から半角が多く、書き換えのたびに全角へ寄せる |
| 波ダッシュ | **〜**（U+301C）に統一 | 「～」（U+FF5E）を使わない |
| ダッシュ | **—**（em dash）に統一 | 「―」を使わない |
| 数字 | 半角 | 「1,390冊」のようにカンマを入れる |
| 年度と課程 | **`build/data/site-meta.json` の `admissionLabel` をそのまま使う**（2026-09 時点は「2027年度入試に向けて順次確認・更新中」）。課程は `curriculumLabel`（「新課程」） | ここに年度を直接書かない。書くと `site-meta.json` を直したときに置き去りになる（実際、以前ここに「2026年度入試対応（新課程）」と書いてあり、正本が 2027 年度へ進んだあとも残っていた）。「2026 新課程対応」のように年度と課程をつなげて書かない。新課程入試は 2025 年度入試から始まっており、年度と課程は別のこと |
| 偏差値 | 基準模試を書く | 「河合塾全統記述模試の換算」 |
| 難易度 | **1〜10 の 10 段階** | 「1〜5 段階」と書かない。役割の 5 段階と混同しない |

### 非日本語文字を混ぜない

LLM で下書きを作ると、簡体字（训练・这・对）やハングル（까지）が混ざることがある。
`build/check-site.mjs` がハングル・キリル文字・JIS X 0208/0213 に無い CJK 文字を検出して**落とす**。

ギリシャ文字の α・β は書名（リードα・ExcelΑ など）に実在するので例外にしている。

## 6. 定型文を全ページに置かない

同じ段落が 1,000 ページ以上に出ると、読者にも検索エンジンにも「薄い」ページの集まりに見える。

- 参考書の選び方の一般論は、[データの作り方](/methodology/) と解説記事に 1 か所だけ置く
- 書籍ページの本文には、**その本でしか成り立たない文**だけを書く（向いている人・同じ役割の中での位置）
- 難易度の定義のような共通の説明は、`build/lib/scale.mjs` の折りたたみコンポーネントで出す。文章として書き下ろさない
- ページ末尾の CTA は共通でよい。ただし科目名・冊数は変数にする

`build/check-site.mjs` は、書籍ページの本文段落が何ページに重複しているかを数え、
**半数以上のページに同じ段落があれば落とす**。

---

## 7. meta description と title

- `description` は **120 字以内**。本文の頭を写さず、検索結果で「自分に関係あるか」を判断できる要素だけを並べる
- `title` は **60 字以内**。「書名 + 何が分かるか + サイト名」
- 同じ `title` のページを作らない（同名の本は分野または出版社を添えて区別する）

---

## 8. 書き換えの手順

1. `node build/check-site.mjs` を流し、禁止語・定型文・非日本語文字の指摘を出す
2. 科目単位で書き換える（1 冊ずつコミットしない。1 科目 1 コミット）
3. 書き換えたら生成スクリプトを流し直し、`node build/check-site.mjs` を通す
4. 元の文は git 履歴に残る。加えて、大きく書き換えるときは `data/_backup/` に書き換え前のスナップショットを置く
