# Search Console のインデックス状況の読み方

`ページのインデックス登録` の「未登録」に出る理由ごとに、**こちらで直すもの**と
**待つしかないもの**を分ける。分けないと、正常な挙動を不具合として追いかけることになる。

正本の分担:

| 内容 | 正本 |
|---|---|
| 手動設定の実施状況（Search Console の送信・確認） | `README.md` の「運営者が行う手動設定」 |
| 公開サイトのリダイレクト実測 | `build/check-production.mjs`（`npm run check:production`） |
| リポジトリ側の URL 表記の検査 | `build/check-site.mjs`（`npm run check:site`） |
| 理由ごとの判断 | **この文書** |

---

## 1. 「ページにリダイレクトがあります」

### 何を意味するか

Google が取りに行った URL が 200 ではなく 301 を返した、という意味。
**リダイレクト先のページは別途インデックスされる**ので、この件数そのものが
順位や表示回数を下げるわけではない。無駄になるのはクロールの往復だけ。

### このサイトで 301 が返る場所は 3 種類しかない（2026-09-07 実測）

| 元 | 先 | 状態 |
|---|---|---|
| `http://route-taizen.com/…` | `https://route-taizen.com/…` | **正しい。消さない** |
| `https://www.route-taizen.com/…` | `https://route-taizen.com/…` | **正しい。消さない** |
| `https://route-taizen.com/about`（末尾スラッシュ無し） | `https://route-taizen.com/about/` | **作ってはいけない** |

上 2 つは GitHub Pages がホストを正規化するもので、こちらの設定では消せないし、
消すべきでもない（消えると重複したホストが 200 で並ぶ方が悪い）。
Search Console のプロパティが**ドメインプロパティ**（`route-taizen.com`）なら、
この 2 件が「ページにリダイレクトがあります」として常時カウントされる。
**件数が 2 前後で横ばいなら、これが理由。対応不要。**

3 つ目だけがこちらの不備。GitHub Pages は実在するディレクトリを末尾スラッシュ無しで
要求されると 301 を返す。貼った側は最終的に同じページへ着くので、手元では気づかない。

### 機械で防いでいること

- `npm run check:site`
  - 内部リンク（`href="/…"`）の末尾スラッシュ欠落を**エラーで落とす**
  - 自サイトを `http://` や `www.` で指している箇所を**エラーで落とす**
  - `sitemap.xml` の `<loc>` が正規ホスト・末尾スラッシュ・実在ページであることを検査する
  - noindex でないページが `sitemap.xml` から漏れていないかを逆向きにも検査する
- `npm run check:production`
  - 代表 URL がリダイレクトを踏まずに 200 で返ることを実測する
  - `http://` と `www.` が `https://route-taizen.com/` へ 301 することを実測する
    （**期待どおりの 301 が消えていないか**も検査対象にしてある）

### 件数が増えたときの調べ方

1. `npm run check:site` を流す。落ちればそこが原因。直してから再配信する
2. 通るなら `npm run check:production` を流し、代表 URL の実測を見る
3. どちらも通るのに件数が増えているなら、外部サイトが末尾スラッシュ無しの URL を
   貼っている可能性が高い。**その場合はこちらで直せない**（301 は正しく機能している）。
   Search Console の該当行から URL を書き出して、上の 3 種類のどれかを判定する

## 2. 「検出 - インデックス未登録」

### 何を意味するか

Google は URL の存在を知っているが、**まだクロールしていない**。
「クロール済み - インデックス未登録」（＝読んだうえで載せないと判断した）とは別物で、
こちらは品質評価の結果ではない。

### 主な要因

- **サイトが新しい。** 新規ドメインにはクロール速度の上限が低く設定される。
  ページ数が多いほど、全部を読み終えるまでの期間が長くなる
- **1 ページあたりの独自性が薄い。** 生成ページが多いサイトでは、
  似た構成のページから順に後回しにされる
- **内部リンクが遠い。** どのページからも 1 回しかリンクされていないページは優先度が下がる

### 判断の目安

`登録済み ÷ (登録済み + 検出-未登録)` が**時間とともに上がっているか**を見る。
上がっているなら進行中で、待つのが正解。横ばい・低下なら中身の問題を疑う。

**スナップショットは必ず日付とともに記録する。**（下の「4. 実測の記録」）

### 内部リンクの薄いページを出す

被リンクが 1 本しかないページは、`npm run check:site` では落ちない（孤立ではないため）。
必要なときは手元で数える:

```bash
node -e '
const fs=require("fs"),path=require("path");
const skip=new Set(["node_modules",".git","dist","build","test","e2e","docs","data",".github","assets","test-results"]);
function walk(d,a=[]){for(const e of fs.readdirSync(d,{withFileTypes:true})){if(skip.has(e.name))continue;const p=path.join(d,e.name);e.isDirectory()?walk(p,a):e.name.endsWith(".html")&&a.push(p);}return a;}
const files=walk("."),u=f=>"/"+(path.dirname(f)==="."?"":path.dirname(f).replace(/^\.\//,"")+"/");
const all=new Set(files.map(u)),inb=new Map([...all].map(x=>[x,new Set()]));
for(const f of files){const s=u(f);for(const m of fs.readFileSync(f,"utf8").matchAll(/href="([^"]+)"/g)){let h=m[1].replace("https://route-taizen.com","").split("#")[0].split("?")[0];if(all.has(h)&&h!==s)inb.get(h).add(s);}}
[...inb].map(([k,v])=>[k,v.size]).sort((a,b)=>a[1]-b[1]).filter(a=>a[1]<=1).forEach(a=>console.log(a[1],a[0]));
'
```

## 3. 「クロール済み - インデックス未登録」

読んだうえで載せないと判断された状態。件数が少ないうちは個別要因（ほぼ同じ内容の
別ページがある、本文が短い）であることが多い。**件数ではなく URL を見る。**
Search Console の該当行を開き、書影・書名・説明以外に独自の記述があるかを確認する。

## 4. 実測の記録

**推測で埋めない。** 管理画面を見た日付と数値をそのまま残す。

| 日付 | 登録済み | 未登録 | リダイレクト | 検出-未登録 | クロール済み-未登録 |
|---|---|---|---|---|---|
| 2026-09-07 | 1130 | 351 | 2 | 346 | 3 |

2026-09-07 時点の読み: 登録が始まったのは 2026-08-19 で、3 週間で 1130 / 1481。
リダイレクト 2 件はホスト正規化（`http://` と `www.`）で説明が付く件数であり、
リポジトリ側には 301 になる URL が 1 件も無いことを `npm run check:site` と
`npm run check:production` で確認済み。**この時点では追加の対応は不要と判断した。**

次にこの表へ 1 行足すとき、リダイレクトが 2 から増えていたら「1. の調べ方」を実行する。

### 2026-09-08 に 161 ページ増やしたことによる影響

この日、大学別ページ（`/univ/<slug>/` 160 枚と一覧 1 枚）を追加し、sitemap の URL は
1,482 → 1,643 になった。**次にこの表を読むとき、「検出 - インデックス未登録」は
一時的に増える。**新しく sitemap に載った URL は、Google が存在を知ってから
クロールするまでのあいだ、必ずこの区分に入るためである。

- **増えたこと自体は不具合ではない。**「2. 検出 - インデックス未登録」の判断の目安
  （`登録済み ÷ (登録済み + 検出-未登録)` が時間とともに上がっているか）で見る
- ただし**数週間たっても `/univ/` 配下がまったく登録されない**なら、内容が薄いと
  判断された可能性がある。その場合は URL を書き出して「3. クロール済み - インデックス
  未登録」の手順で個別に確認する
- 「ページにリダイレクトがあります」は増えないはず。`npm run check:site` が
  `/univ/` を含む全ページの末尾スラッシュとホスト表記を検査している
