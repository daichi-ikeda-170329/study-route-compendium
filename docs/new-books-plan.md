# 新刊の掲載と X 投稿の運用設計

新しく発売された参考書と、サイトに載っていない既刊を随時足すための仕組み。

策定日: 2026-08-28

運用の正本は 2 つに分かれる。X アカウント全体の設計は
[x-account-plan.md](x-account-plan.md)、新刊まわりはこのファイル。

## 1. 目的

[x-account-plan.md](x-account-plan.md) が定めた 3 段（認知 → 来訪 → 収益）のうち、
このファイルが担うのは **収録の鮮度** である。

参考書は毎年 3 月と 9 月に集中して出る。新刊が出た直後にサイトへ載り、X で
「もう載っている」と示せることが、既存の受験系アカウントに対する差になる。
逆に、新刊が半年載らないサイトは「更新が止まっている」と読まれる。

## 2. 全体の流れ

**月 1 回、X の投稿文を作るセッションの中でまとめてやる。** 新刊の調査だけを
別の機会にすると、思い出す回数が増えて続かない。

```
毎月 1 日：GitHub Actions が gen-x-posts.mjs を実行
          → docs/x-posts/YYYY-MM.md（B・C・D 型が空欄／新刊調査の手順つき）
                              ↓
池田さんが Claude にファイルを渡す
                              ↓
① Claude が新刊を調査する（出版社の公式ページ＋検索）
② 掲載する本を build/data/new-books.json に足す
③ 注入して再生成する
④ gen-x-posts.mjs を --force で流し直す → F 型が入った月次ファイルになる
⑤ Claude が B・C・D 型を書く
                              ↓
池田さんが 1 か月分をまとめて予約投稿に貼る
```

**①〜④ を ⑤ より先にやる。** 新刊が見つかると F 型の枠が増え、その分 A 型が
減るので、順番を逆にすると月次ファイルの作り直しになる。

## 3. 前提と決定

**決定 1: 検知を自動化しない。月次セッションで Claude が調べる。**

楽天ブックス書籍検索 API を週次で叩く案を実装まで進めたが、捨てた。
アプリ登録が **IP アドレスの許可制**で、登録した IP 以外からのリクエストは
拒否される仕様だったためである。GitHub Actions の実行マシンは共有プールから
割り当てられ、IP レンジは 7,000 以上あって定期的に入れ替わる（`api.github.com/meta`
の `actions` で確認できる）。フォームに登録しきれない。

池田さんの自宅 IP を登録してローカル実行する案も残ったが、回線の都合で IP が
変われば黙って止まる。**月 1 回どのみち Claude のセッションを開くのだから、
そこで調べればよい**という判断に落ち着いた。

**決定 2: 新刊のメタデータのうち、判断が要る項目は空のまま掲載する。**

新刊は池田さんも Claude も現物を読んでいない。`diff`（難易度 10 段階）・
`hensachi`・`pros`・`cons`・`bestFor` は中身を知らないと書けない。ここを推測で
埋めると、README の「推測で著者名を補わない」と同じ種類の捏造になり、既存の収録全冊との難易度の物差しも狂う。

**出版社の公式ページには対象レベルや問題数が載っていることがあるが、それでも
難易度は書かない。** このサイトの 10 段階は既存の全冊との相対評価であり、
1 冊だけを見て決められる数字ではないからである。

検証できる事実（書名・出版社・ISBN・刊行年・収録範囲）と役割（`stage`）だけを
入れ、`provisional: true` を立てて「新刊・評価準備中」と明示する。

**決定 3: 新刊は `ROUTES`（志望校別ルート）に入れない。**

ルート採用は既存書との比較判断であり、現物未読では決められない。図鑑・検索・
書籍ページには出すが、ルートと診断結果には出さない。評価が固まってから手で入れる。

**決定 4: F 型（新刊速報）は月次カレンダーに組み込む。**

調査が月次になったので、単発で出す理由が無くなった。投稿を貼る作業が月 1 回・
1 ファイルで完結する。新刊の本数だけ A 型（図鑑カード）を減らして合計 28 本を保つ。

## 4. 調査 — 月次セッションでやること

手順の実体は毎月の `docs/x-posts/YYYY-MM.md` の「新刊調査」節に出る。
`build/gen-x-posts.mjs` の `survey()` が生成しており、**この設計書ではなく
生成物のほうを読んで作業する**（調査先や収録状況が毎月の実データで出るため）。

### 調べに行く先

`build/data/publishers.json` が正本。収録済みの本の出版社を冊数順に並べてある。
公式ページの巡回と検索の両方をやる。

**URL は改修で切れる。開けなかったら `publishers.json` を直す。**
放置すると、その出版社だけ静かに調査から抜け落ちる。

### 掲載しないもの

- 大学受験以外（小中学・高校入試・英検などの資格・専門学校・大学院）
- 改訂版のうち、同じ本が既に収録されているもの（版が変わっただけなら既存の `year` を直す）
- 赤本・青本などの大学別過去問（毎年出るうえ、収録済みの枠で足りている）
- 学校専売で一般に買えないもの（書影も取れず、読者が入手できない）

### 未収録かどうかの確かめ方

月次ファイルに出る「収録している出版社」と「刊行年の分布」で当たりを付け、
判断がつかないものは検索の索引（`assets/js/book-index.js`）で書名を引く。

**直近の年の冊数が少なければ、新刊を取りこぼしている。** 分布を出しているのは
この確認のためである。

## 5. 承認 — `build/data/new-books.json`

掲載を決めた本をこの JSON に足す。

```json
{
  "books": [
    { "id": "…", "subject": "english", "name": "…", "official": "…",
      "pub": "…", "isbn13": "…", "year": 2026, "stage": "tango",
      "provisional": true }
  ]
}
```

必須は `id` / `subject` / `name` / `official` / `pub` / `year` / `stage`。

**`stage`（役割）だけは事実ではなく判断だが、これが無いと図鑑のどこにも置けない**
ため必ず決める。書名と出版社の紹介文から役割は判断できる（単語帳なのか問題集なのか）。
難易度は判断できないので空のままにする。

評価が固まったら、この JSON から該当エントリを消し、科目 HTML の `BOOKS` 配列本体へ
`provisional` を外した完全なエントリとして移す。**JSON に残っている数が
「評価の残作業」そのものになる。**

## 6. 注入 — `build/apply-new-books.mjs`

各科目 `index.html` に置いたマーカー区間の中身を丸ごと書き換える。

```js
/* NEW BOOKS — 自動生成。build/apply-new-books.mjs が書き換える。手で編集しない */
/* /NEW BOOKS */
```

`build/lib/extract.mjs` は `vm` で script を実行して定数を回収するので、
`BOOKS.push()` された分もそのまま拾える。数学の `ADDITIONAL BOOKS` 区画とは
別物として並置し、既存を巻き込まない。

**マーカーが見つからない科目があったらエラーで止める。** 黙って何もしないと
掲載漏れに気づけない。

id の衝突と存在しない `stage` もここで止める。突き合わせの基準は
**マーカー区間を空にした状態**にしてあり、何度流しても同じ結果になる。

## 7. 未評価の表示

`provisional === true` を唯一の根拠にする。バッジ文言は「新刊・評価準備中」。

| 画面 | 扱い |
|---|---|
| 科目トップの図鑑（一覧・モーダル） | 出す。難易度・到達目安の欄はバッジに置き換える |
| 生成ページの一覧 `/<科目>/books/` | 出す。カードのバッジのみ |
| 生成ページの書籍ページ | 出す。難易度・強み・注意点・向いている人の節は出さない |
| 検索 | 出す |
| 志望校別ルート | 出さない（`ROUTES` に入れないので自動的に対象外） |
| 3 分診断の結果 | 出さない（同上） |
| おすすめ | 出さない（ルート採用回数で選ぶため自動的に対象外） |
| X の A 型（図鑑カード） | 出さない。難易度と向く人を書けないため |
| X の F 型（新刊速報） | ここでのみ出す |

### 数字を持たない本が壊す場所

`provisional` な本は `diff` を持たない。次の 3 種類の壊れ方があるので、
描画側で必ず分岐する。

1. `${b.diff}` の素の埋め込み → 画面に `undefined` が出る
2. `b.pros.map()` / `b.subjects.split()` / `b.fb.bg` → **TypeError で描画そのものが止まる**
3. `d<=2 ? … : 最難関` 形の分類 → 比較が全部 false になり、**静かに最難関へ化ける**

3 が最も危ない。科目トップの `bookLv()`（英語のみ）と `diffColor()` が該当した。
2 は `coverHTML()` が該当し、実際に図鑑の描画が止まることを確認してから直した。

## 8. 冊数の追随 — `build/apply-count.mjs`

`index.html` は 13 箇所（title・meta description・og・twitter・JSON-LD・本文・
統計カード）に冊数を持ち、README の収録数テーブルにもある。

`title` や `meta content` 属性の中に HTML コメントは置けないので、プレースホルダ
方式は採れない。代わりに `build/data/count-state.json` に**前回書き込んだ値**を
持ち、それを新値へ置換する。

**置換件数をログに出し、0 件なら終了コード 1 で止める。** 静かに何もしないと、
冊数だけが古いまま残る。

### 画像に焼き込まれた冊数

| 対象 | 扱い |
|---|---|
| `assets/x-header.png` | SVG が正本としてあるので更新できる。月 1 回、README の Chrome ヘッドレス手順で焼き直す |
| `assets/ogp*.png`（共通 + 7 科目） | `node build/gen-ogp.mjs` で焼き直す。冊数は `BOOKS` から数える |
| `assets/ogp/<科目>/<id>.png` 1,390 枚 | 同上。書名・役割・難易度・到達目安をデータから入れる |

**2026-09-04 に作り直した。** それまでの `assets/ogp*.png` は元になる SVG も生成
スクリプトもリポジトリに無く（初期コミットで PNG が直接追加されたきり）、画像に焼き込んだ
冊数を更新できないため据え置きを明示的な決定としていた。現在は SVG テンプレート
（`build/ogp/`）と生成スクリプト（`build/gen-ogp.mjs`）がリポジトリにあり、
作り忘れは `node build/gen-ogp.mjs --check` が CI で落とす。

## 9. F 型（新刊速報）

`build/gen-x-posts.mjs` が月次ファイルの中に作る。掲載済みの新刊のうち、まだ
投稿していないものが対象（記録は `docs/x-posts/used.json` の `newPosted`）。

**難易度も向いている人も書かない。** 書けるのは書名・出版社・刊行年・収録範囲・
役割・書籍ページの URL だけである。`utm_campaign=rt_f_new`。

日付は**月初から割り当てる**。新刊は鮮度が価値なので、月末に回すと意味が薄れる。
1 か月に出す上限は 4 本（`F_MAX`）で、新刊が大量に出た月に月次ファイルが
新刊だらけになるのを防ぐ。

### 同じ月を作り直しても内容が入れ替わらない

`used.json` は「どの月に出したか」を `byMonth` で覚えている。`--force` で
作り直すとき、その月に自分が選んだ本は「既出」から外して選び直すため、
**A 型の顔ぶれが総入れ替えにならない。** これが無いと「新刊を調べてから
月次ファイルを作り直す」という運用そのものが成り立たない。

F 型に押し出された A 型の本は `used` に記録されないので、翌月以降に回る。

## 10. 自動化の切り分け

| 工程 | 担当 | 頻度 |
|---|---|---|
| 月次ファイルの生成 | `build/gen-x-posts.mjs` | GitHub Actions が毎月 1 日に実行 |
| 新刊の調査 | Claude | 月 1 回、B・C・D 型を書くのと同じセッション |
| 掲載の判断 | 池田さん | 同上（Claude の提案を承認する） |
| `BOOKS` への注入と再生成 | `apply-new-books.mjs` + `generate-*.mjs` | 同上 |
| 冊数の更新 | `apply-count.mjs` | 同上 |
| F 型の本文生成 | `gen-x-posts.mjs --force` | 同上 |
| X への投稿 | 池田さん | 月 1 回 |
| 画像の焼き直し | 池田さん | 月 1 回（`x-header` のみ） |

外部サービスの登録も API キーも要らない。**動かすのに必要なのは月 1 回の
Claude セッションだけ**である。

## 11. 池田さんが行う操作

初回に必要な設定は無い。毎月 1 日に生成された `docs/x-posts/YYYY-MM.md` を
Claude に渡し、「新刊調査と B・C・D 型をお願い」と言えばよい。

Claude が調査結果を出したら、掲載する本を選んで承認する。そのあとの注入・
再生成・F 型の生成は Claude が流す。最後に 1 か月分をまとめて予約投稿に貼る。

## 12. リスク

| リスク | 対処 |
|---|---|
| 調査を忘れる | 月次ファイルの冒頭に手順が出るようにしてある。ファイルを開けば目に入る |
| 未評価の本が増え続け、評価が追いつかない | `new-books.json` の件数が残作業そのもの。増えすぎたら掲載ペースを落とす |
| 「評価準備中」ばかりの図鑑になり信頼を損なう | 掲載は選んだ本だけにする。見つけた本を全部入れない |
| 出版社サイトの改修で調査先が切れる | 開けなかったら `publishers.json` を直す。月次ファイルにもそう書いてある |
| 注入スクリプトが 5 科目の HTML を壊す | マーカー欠落はエラーで停止。`test/new-books.test.mjs` で往復を検証する |
| 冊数だけが古いまま残る | 置換 0 件を異常として終了コード 1 で止める |
| 調査の見落とし | 網羅は保証できない。**池田さんが書店や X で見つけた本を直接 `new-books.json` に足す口も同じ経路である**（掲載後の処理はまったく同じ） |
