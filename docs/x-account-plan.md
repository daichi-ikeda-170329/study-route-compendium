# X アカウント運用計画

ルート大全（https://route-taizen.com/）を X で広め、サイトへの流入と書籍リンク経由の収益につなげるための運用設計。

策定日: 2026-08-28

## 1. 目的

順に、次の 3 つを達成する。前の段が満たされないと次の段は動かない。

1. **認知** — 受験生に「ルート大全というサイトがある」と知ってもらう
2. **来訪** — X からサイトへ来てもらい、志望校別ルートまで到達してもらう
3. **収益** — サイト内の書籍リンク（Amazon アソシエイト・楽天アフィリエイト）を踏んでもらう

X は 1 と 2 を担う。**3 はサイト側の仕事であり、X 上では行わない**（理由は 2 節）。

## 2. 前提と制約

### 確認済みの事実

| 事項 | 内容 | 出典 |
|---|---|---|
| X の予約投稿 | 無料アカウントでも使える。**ブラウザ版のみ**でアプリからは不可 | [予約投稿の解説](https://sinis-x.tetemarche.co.jp/blog/x-reserve) |
| X API の無料枠 | **2026 年 2 月に廃止**。従量課金へ移行。投稿 1 回 $0.015、**URL を含む投稿は $0.200**。最低 $5 のクレジット購入が必要 | [X API 料金](https://api.sorsa.io/blog/twitter-api-pricing-2026)、[無料枠終了の解説](https://note.com/unikoukokun/n/n095511dbd5e3)、[公式ドキュメント](https://docs.x.com/x-api/introduction) |
| Amazon アソシエイト | リンクを貼る URL はすべて事前登録が必要で、SNS も例外ではない。SNS ページの目安として**オーガニックフォロワー 500 人以上**が挙げられている | [公式ヘルプ](https://affiliate.amazon.co.jp/help/node/topic/GM3CX5D6DSLGVSJD)、[規約解説](https://www.cyber-records.co.jp/amazon-associates-sns-compliance-rules/) |

### そこから導いた決定

**決定 1: X の投稿にアフィリエイトリンクを貼らない。必ず route-taizen.com に送る。**

規約リスクを避けられる。加えて、サイトに来てもらえば 1 冊ではなくルート全体を見てもらえるため、収益面でもこちらが有利になる。

**決定 2: X API による自動投稿を採用しない。**

「完全無料でやりたい」という方針と両立しない。URL 付き投稿を週 7 本流すと月約 $6（約 900 円）かかる。

**決定 3: ブラウザ自動操作による投稿も採用しない。**

技術的には可能だが、X の規約上グレーで、スパム判定による凍結リスクがある。育てたアカウントを失う損失が、削減できる手作業に見合わない。

**決定 4: 手作業は「月 1 回、生成済みの本文を予約投稿にコピペする」だけに圧縮する。**

## 3. ターゲット

| 優先 | 層 | 役割 |
|---|---|---|
| 1 | 浪人生 | X の受験界隈で最もコミュニティが濃い。拡散の起点 |
| 1 | 現役高 3 | 母数が最大で反応が速い。ただし共通テスト後に一斉に離れる |
| 2 | 高 1・高 2 | 蓄積先。志望校から逆算するルートは時間が残っている層に最も刺さる |
| 3 | 保護者・指導者 | 購入決定権を持つが X での拡散が遅い。初期は狙わない |

高 3 と浪人生だけを狙うと毎年フォロワーがリセットされる。**高 1・高 2 を同時に貯めることが、翌年以降の土台になる。**

## 4. 投稿タイプ

5 タイプを定義する。それぞれ狙いと作る手間が違う。

| | タイプ | 中身 | 生成 | 狙い |
|---|---|---|---|---|
| **A** | 図鑑カード | 1 冊を役割・難易度・似た本との違いで紹介する定型 | スクリプト | 毎日動かす。ネタが枯れない |
| **B** | ルート提示 | 「この志望校で、ここまで終わった人の次の 1 冊」 | Claude | サイトへの流入。収益に最も近い |
| **C** | 判断基準 | 参考書の選び方の原則を語る | Claude | フォロワー獲得。最も伸びる |
| **D** | 対決 | 2 冊をアンケートで戦わせ、翌日データで決着 | Claude | 参加とリプライ。拡散 |
| **E** | エンタメ | 1,052 冊のデータから出る「面白い事実」 | スクリプト | 認知の外周。受験生以外にも届く |

### D（対決）は 2 投稿セットにする

初日にアンケートで問い、翌日にデータで答え合わせをする。盛り上がりを作る役と流入を作る役を分けるためである。

- **初日** — 「ネクステ vs Vintage、どっち派？」＋ X のアンケート機能（無料）
- **翌日** — `BOOKS` が持つ難易度・役割・接続先の違いを提示し、両方の詳細ページへ送る

後半は 1,052 冊のデータを持っている者にしか書けない。**ここが他の受験アカウントに対する差別化になる。**

### E（エンタメ）はデータから機械抽出する

`BOOKS` から実際に取れる事実だけを使う。捏造しない。

- 収録語数が最も多い単語帳
- 同じ著者が最も多くの冊数を出している科目
- ルートへの採用回数が最も多い 1 冊（`generate-picks.mjs` が既に持っている集計）

## 5. フェーズ設計

**最初の 4 週間は、どのタイプを投稿しても数字が取れない。** フォロワーがゼロのアカウントはインプレッションが 2 桁台にとどまり、タイプ間の比較が統計的に成立しないためである。ここで「A は伸びなかった」と結論を出すと判断を誤る。

| フェーズ | 期間 | やること |
|---|---|---|
| **1 立ち上げ** | 第 1〜4 週 | 検証はしない。フォロワー獲得に全振りし、C と D を厚く打つ。並行してサイト側の導線を実装し、既存の月 100〜1,000 人の訪問者をアカウントへ流す |
| **2 検証** | 第 5〜12 週 | 5 タイプを毎週 1〜2 本ずつ回し、utm で数字を取る。第 8 週に中間判断、第 12 週に確定 |
| **3 定常** | 第 13 週〜 | 確定した配分で運用 |

フェーズ 2 の後半は 11〜12 月にあたり、共通テスト直前で受験界隈の反応が最も濃くなる時期と重なる。

## 6. 検証の設計

### utm の付け方

自分の投稿に貼る URL にだけ `utm` を付ける。**ユーザーが共有ボタンから流した URL には付けない。**

```
https://route-taizen.com/english/?utm_source=x&utm_medium=social&utm_campaign=rt_d_battle
```

| タイプ | utm_campaign |
|---|---|
| A 図鑑カード | `rt_a_catalog` |
| B ルート提示 | `rt_b_route` |
| C 判断基準 | `rt_c_principle` |
| D 対決 | `rt_d_battle` |
| E エンタメ | `rt_e_fun` |

こう分けると、GA4 上で **自分の投稿由来（utm あり）** と **ユーザーの共有由来（utm なし・referrer が t.co）** が自然に切り分けられる。

### 測る指標

4 層に分けて測る。混同すると判断を誤るためである。

| 層 | 指標 | 取得元 |
|---|---|---|
| 到達 | インプレッション | X の投稿アナリティクス |
| 反応 | いいね・リポスト・リプライ・プロフィールクリック | 同上 |
| 流入 | utm 経由のセッション数 | GA4 |
| 深さ | 流入後のページ数、書籍リンクのクリック到達率 | GA4 |

### 判断の基準

**「反応は取れるが流入しない」タイプと「反応は薄いが流入が濃い」タイプを同じ物差しで比べない。** 前者は認知役、後者は主力役として、役割を変えて両方残す判断があり得る。C が前者、B が後者になると予想している。

第 12 週に、タイプごとに次のいずれかを決める。

- **主力** — 流入と深さが取れている。本数を増やす
- **認知役** — 反応は取れるが流入が薄い。本数は維持し、リンクの置き方を変えて再検証する
- **停止** — 反応も流入も取れない。やめる

## 7. 自動化の切り分け

| 工程 | 担当 | 頻度 | Claude のトークン |
|---|---|---|---|
| A・E 型の本文生成 | `build/gen-x-posts.mjs` | GitHub Actions が月次実行 | **ゼロ** |
| B・C・D 型の本文作成 | Claude | **月 1 回**、4 週分をまとめて | 月 1 セッションのみ |
| 投稿 URL への utm 付与 | スクリプト | 自動 | ゼロ |
| X への投稿 | 池田さん（予約投稿にコピペ） | 月 1 回 | — |
| 数字の集計 | 池田さんが GA4 と X の数値を貼る | 月 1 回 | 小 |

トークンを食う原因は 2 つある。**毎週 Claude に頼むこと**と、**1,052 冊のデータを Claude に読ませること**である。どちらも潰す。

- A・E 型は `BOOKS` から機械的に作れるので LLM を使わない
- B・C・D 型を書く月 1 セッションでは、スクリプトが候補データを絞って出力し、Claude はその抜粋だけを読む。**科目トップの HTML 全文は読まない**

### 生成物の受け渡し

GitHub Actions が毎月 1 日に 4 週分を生成し、`docs/x-posts/YYYY-MM.md` としてコミットする。池田さんはそのファイルを開き、X のブラウザ版の予約投稿画面にコピペする。

## 8. サイト側の実装

**現在の共有ボタンには `via=` が無い。誰かが診断結果を共有してもアカウントに一切ひもづかない。** 月 100〜1,000 人の既存訪問者は初期フォロワーの最大の供給源になるため、ここが最優先である。

| # | 作業 | 対象 |
|---|---|---|
| 1 | intent URL に `via=route_taizen` を追加 | `assets/js/share.js`（`shareBox`）、`build/lib/parts.mjs`（`shareBar`） |
| 2 | `twitter:site` メタを全 1,134 ページに追加 | `build/lib/parts.mjs` の `head()`、手書き 7 か所（ポータル・科目トップ 5・404） |
| 3 | フッターとポータルに X アカウントへの導線 | `build/lib/parts.mjs`、`index.html`、科目トップ 5 |
| 4 | `build/gen-x-posts.mjs` の新規作成 | 新規 |
| 5 | GitHub Actions の月次ワークフロー | `.github/workflows/` |
| 6 | 書籍リンクのクリックを GA4 で計測 | 既存の `track()`（`share.js:200`）を拡張 |

作業 2 と 3 は生成ページの共通パーツと手書き HTML の両方に入れる必要がある。検索ボックスと同じく **`rg` で全箇所を出してから直す**（README の「参考書検索」節と同じ注意が当てはまる）。

## 9. アカウントの設定値

| 項目 | 値 |
|---|---|
| ハンドル | `@route_taizen` |
| 表示名 | `ルート大全の中の人｜参考書1,052冊` |
| アイコン | `assets/x-icon.png`（400×400） |
| ヘッダー画像 | `assets/x-header.png`（1500×500） |
| リンク | `https://route-taizen.com/` |

### 画像

どちらも `assets/` に PNG と、その元になる SVG を置いてある。SVG を直したら
Chrome のヘッドレスで書き出し直す（README の「X アカウント」を参照）。

- **アイコン** `assets/x-icon.png` — X は円形に切り抜くため、favicon の「角のオレンジ」は
  そのまま使えない。円に合う縁のリングに置き換え、「全」を中央に据えてある
- **ヘッダー** `assets/x-header.png` — 左下にアイコンが重なるため x 310 より左には何も置かない。
  「全」のタイルも置いていない（アイコンと同じ字が 2 つ並ぶため）。代わりに収録科目を出す

### プロフィール文

```
参考書1,052冊を全部調べて図鑑にしました。志望校から逆算する
ルートを無料公開中。現役大学生／受験経験あり／指導経験あり。
「その参考書、本当にあなたに要りますか？」を毎日考えています。
📚 route-taizen.com
```

中の人は匿名だが人格を持たせる。実名・顔は出さない。プロフィールに書く経歴は事実の範囲にとどめる。

### 固定ポスト

3 分診断へ送る。診断は参加型で結果を共有でき、その共有には `via=` が入るため、**固定ポスト自体が拡散装置として働く。**

## 10. 池田さんが行う操作

アカウント開設は代行できない（サインアップ・パスワード入力・電話認証）。開設後は次の 3 つだけである。

**初回のみ**

1. X アカウントを開設し、9 節の値を設定する
2. `@route_taizen` が取得できたかを Claude に伝える（取れていなければ実装の `via=` を差し替える）

**毎月 1 回（所要 30 分程度）**

3. `docs/x-posts/` の当月分ファイルを開き、X のブラウザ版の予約投稿画面にコピペして日時を設定する
4. 前月の数字（X のインプレッション・エンゲージメント、GA4 の utm 別セッション）を Claude に渡す

## 11. KPI

| 時点 | フォロワー | X 経由の月間セッション |
|---|---|---|
| 第 4 週（フェーズ 1 終了） | 100 | 30 |
| 第 12 週（フェーズ 2 終了） | 500 | 150 |

フォロワー 500 人は、Amazon アソシエイトが SNS ページの目安として挙げている水準と一致する。**この方針では X にアフィリエイトリンクを貼らないため必須ではないが、将来その選択肢を持つための節目として置く。**

これらは目標であって予測ではない。ゼロから立ち上げるアカウントの伸びは事前に保証できない。

## 12. 未確認事項

実行前に確かめる必要があるもの。

| 事項 | 確かめ方 | 誰が |
|---|---|---|
| `@route_taizen` が取得可能か | X の登録画面で確認 | 池田さん |
| GA4 の拡張計測で外部リンククリックが有効か | GA4 管理画面 →「データストリーム」→「拡張計測機能」 | 池田さん（Claude は管理画面を見られない） |
| 無料アカウントで投稿アナリティクスがどこまで見えるか | 実際に投稿して確認 | 池田さん |

## 13. リスク

| リスク | 対処 |
|---|---|
| 中の人の経歴が疑われる | 事実の範囲を超えて書かない。実績を盛らない |
| C 型（判断基準）の投稿が炎上する | 特定の参考書・講師・予備校を否定する形で書かない。「合う人／合わない人」の形にする |
| D 型（対決）が煽りと受け取られる | 必ず翌日にデータで決着をつけ、どちらも役割が違うだけだと示す |
| 共有 URL のスキーマ変更で過去の共有が壊れる | README の「`v` を上げる運用ルール」に従う。X 上の過去投稿は修正できないため、スキーマ変更は慎重に |
| 投稿が続かない | フェーズ 1 で A・E 型の自動生成を先に用意し、手が空かない月でも流れる状態を作る |
