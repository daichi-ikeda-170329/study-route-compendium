## 2. 診断

### 検索流入が 08-26 から落ちた理由

3 つが重なっている。どれか 1 つに決め打ちしない。

1. **Google の 8 月コアアップデート（08-26 開始・09-21 展開完了）と時期が一致する。** 表示回数の
   減り始めが 08-26 で、崖になった 09-05 も展開の途中。手動対策は無いので、アルゴリズムの評価替え
2. **公開直後の「新規サイトの優遇」が切れた。** 08-22 公開 → 08-24〜26 に 1 日 1,000 表示は、
   評価が定まる前の一時的な露出。その後の実力値は 09-11 以降の 1 日 30〜40 表示
3. **サイトの大半が「書誌 + 200 字の解説 + 共通テンプレート」の薄いページ。** 1,390 冊のうち
   志望校別ルートの本編に入っているのは約 360 冊で、残りは図鑑の 1 項目として存在するだけだった。
   AdSense が 09-05 に「有用性の低いコンテンツ」と判定したのと同じものを Google 検索も見ている。
   09-03 の 340 冊追加と 09-04 の 1,390 冊の説明文の全面書き換えで、サイト全体が一度に再評価の対象に
   なったことも重なる

**技術的な原因は除外した。** robots.txt は `Allow: /`、全ページ `index,follow`、canonical は自分自身、
sitemap は 1,751 件で本番と一致、09-04 以前の URL は 1 件も消えていない（`git show cb53e34f0~1:sitemap.xml` と比較）。

### 何が効いていて、何が効いていないか

- **効いている**: 書籍ページの「書名＋レベル」検索。競合が薄い本（上級問題精講・漆原・原点からの化学）で
  1〜10 位に入り、CTR 20% で踏まれている。**この型を強くするのが最短**
- **効いていない**: 比較記事による「ネクステ vs ヴィンテージ」型の検索。塾ブログが上位を占め、
  ドメインの評価が無い今は入れない。記事を増やしても当面は流入にならない
- **効いていない**: X。フォロワー 3 人では投稿が誰にも配信されない。加えて外部リンク付きの投稿は X が
  表示を抑えるので、URL を毎回本文に入れる今の形は不利

## 6. サイト全体の精査（2026-09-19）

表示の崩れ・数字の不一致・計測の正しさを、実測で洗った記録。

### 6.1 GA4 の数字の約半分が自分たちのテストだった

GA4 の「ユーザー属性の詳細: 国」を 28 日（08-22〜09-18）で見た実数。

| 国 | アクティブユーザー | エンゲージメント率 | 平均エンゲージメント時間 |
|---|---:|---:|---:|
| 合計 | 28,030 | 9.24% | 3 秒 |
| Japan | 14,344（51.17%） | 10.29% | 6 秒 |
| **United States** | **13,799（49.23%）** | 7.58% | **0 秒** |

**米国の 13,799 は GitHub Actions の E2E。** push のたびに 474 テストが 6 ブラウザ構成で走り、
そのすべてが GA4 に `page_view` を送っていた。平均エンゲージメント時間 0 秒がその証拠で、
実在の読者ではありえない規模（Deck が絞り込んで記録している日次 PV は 1 日 50〜200）。

原因は、`assets/js/analytics.js` の開発環境判定（localhost・127.0.0.1 を除外）が
**独自イベントにしか効かず**、`gtag('config')` が初期化時に自動で送る `page_view` を
素通りさせていたこと。2026-08-29 に Deck 側で「全 PV の 22.6% がローカル混入」と
突き止めて絞り込みを入れたが、それは Deck の表示側の対処で、GA4 の生データは汚れたままだった。

**対応。** `build/lib/parts.mjs` の `CONSENT_DEFAULT` の先頭で、ホスト名が
`route-taizen.com` でなければ `window['ga-disable-G-DQ5WFXEFMX'] = true` を立てる。
これは gtag の公式なオプトアウトで、`page_view` を含む全送信が止まる。
同意の既定値と同じ経路で全ページ（生成 1,755 枚＋手書き 9 枚）に配られる。

**この日以降、GA4 の数字は実在の読者だけになる。** 09-19 より前との比較はできない。

### 6.5 数字の不一致

`npm run check:counts` の全ファイル走査は通っているが、**画像に焼き込んだ数字は対象外**だった。
X のヘッダー画像（`assets/x-header.svg`）が公開当初の **1,052 冊**のままで、
X のプロフィールにその数字が出ていた（実際は 1,390 冊）。

- SVG を 1,390 冊に直し、PNG を焼き直した
- 二度と古くならないよう、`build/apply-count.mjs` の文脈アンカーに SVG を追加した
  （冊数が変われば `--check` が落ちる）
- **PNG を X のプロフィールに上げ直すのは運営者の操作**（アカウント設定の変更にあたる）

X 投稿案の「ルート 42 本」という言い回しも直した。書籍ページの「志望校別ルート N 本」は

### 6.8 同じ検査があったのに見逃していた理由

横スクロールは E2E に「狭い画面でも自サイト由来の横はみ出しが無い」という検査が
**既にあった**のに、7px のはみ出しを 2026-09-19 まで見逃していた。穴が 2 つ重なっていた。

1. **対象ページに参考書一覧が無かった。** 検査していたのはトップ・科目トップ・検索・記録・
   書籍 1 枚の 5 つで、カードが大量に並ぶ `/<科目>/books/` が入っていなかった
2. **Chrome で走っていなかった。** この検査は `cross-browser.spec.mjs` にあり、
   `testMatch` で Safari と Firefox だけを対象にしている。**Safari はグリッドの
   最小幅の扱いが違い、この崩れを再現しない**（実測: 修正前の CSS で Chrome 327px・
   Firefox 327px・Safari 320px）

対応として、Chrome の 4 幅（320 / 375 / 768 / 1366）で走る `flows.spec.mjs` に
「どの幅でもページ全体が横スクロールしない」を新設し、一覧・ルート・大学別を含む 11 ページを
見るようにした。`cross-browser.spec.mjs` 側も対象ページを 5 → 10 に増やし、
要素単位の検査に加えて `scrollWidth <= clientWidth` も見るようにした。

**修正前の CSS に戻すと新しい検査は落ちる**ことを確認済み（`/math/books/ で横スクロールが出る（幅 320px）`）。
検査を足しただけで満足せず、落ちることまで見ないと「捕まえられる」とは言えない。

### 6.10 計測イベントの 9 件は契約だけで未実装だった

README の確認項目「イベントが `docs/analytics-events.md` の表と一致しているか」を
実測で確かめた。**allowlist の 19 件のうち、実際に送っているのは 10 件だけだった。**

| 状態 | 件数 | 内訳 |
|---|---:|---|
| 送っている | 10 | `affiliate_click`（書籍ページ）、`book_search_open`（検索）、`route_save` と共有まわり 8 件（`share.js`） |
| 契約だけで呼び出しが無い | 9 | `subject_open` / `catalog_filter` / `book_open` / `route_start` / `route_complete` / `pace_start` / `pace_complete` / `route_share` / `book_buy_click` |

**科目トップ（図鑑・ルート・診断・ペース計算）の計測は 1 つも実装されていない。**
実ブラウザで科目トップを開き、図鑑・ルート・診断のタブを操作しても `RTAnalytics.track` は
一度も呼ばれなかった（`RTAnalytics` 自体は読み込まれている）。

**不具合ではなく未実装。** git で追うと、allowlist を作った `1891ec25d`（2026-09-04）の
対象は `share.js`・`search.js`・書籍ページの購入リンクの 3 つで、科目トップは最初から
入っていない。その前の版にも科目トップからの送信は 0 件だった。

問題は**文書の書き方**だった。表が allowlist をそのまま並べ、「いつ」欄に
「科目トップを開いた」と書いてあったため、読むと実装済みに見える。
表を「送っている（呼ぶ場所つき）」と「許可しているが、まだ呼び出しが無い」に分け、
`test/analytics.test.mjs` に「『送っている』表に載せたイベントは実際に呼び出しがある」を
足した（嘘を混ぜると落ちることを確認済み）。

**実装は流入が戻ってから。** ページ単位の閲覧は GA4 の `page_view` で取れており、
足りないのは画面の中の行動（診断完了率など）。1 日 30〜40 表示の母数で率を測っても
有意にならないので、いま入れても判断材料にならない。
