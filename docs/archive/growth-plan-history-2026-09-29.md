**横スクロールの原因は `.bcards` のグリッド定義だった。** `grid-template-columns:1fr` は
「中身の最小幅より縮まない」ため、書影の代替表示に入っている長い出版社名
（「教学社（難関校過去問シリーズ）」など）がカードを 327px まで押し広げ、320px の画面で
7px はみ出していた。`minmax(0,1fr)` に変えて解消（`assets/site.css`）。
影響したのは `/math/books/` と `/science/books/` だが、同じグリッドは全科目の一覧・
書籍ページの関連本にも使われているので、同じ条件がそろえば同様に崩れる状態だった。

### 6.4 タップ領域

ヘッダーの検索欄が **20px** しかなく、WCAG 2.5.8 のターゲットサイズ（24px）を割っていた。
枠は 38px あるのに入力欄自体が文字の高さしか無く、枠の上下 9px を押してもフォーカスが
入らない。正本の `assets/js/search.js` の `STYLE` に `align-self:stretch` を足して
**36px** にした（見た目は変わらない。入力欄は背景も枠線も持たないため）。

詳細検索のチェックボックスは 18px だが、**親のラベルが 305×44px** で、ラベル全体が
タップ領域になっている（クリックでトグルする）ので問題なし。
`/progress/` の 1×1 の入力欄は `pointer-events:none` の隠しファイル入力で、ボタンが代理で開く。

### 6.5 数字の不一致

`npm run check:counts` の全ファイル走査は通っているが、**画像に焼き込んだ数字は対象外**だった。
X のヘッダー画像（`assets/x-header.svg`）が公開当初の **1,052 冊**のままで、
X のプロフィールにその数字が出ていた（実際は 1,390 冊）。

- SVG を 1,390 冊に直し、PNG を焼き直した
- 二度と古くならないよう、`build/apply-count.mjs` の文脈アンカーに SVG を追加した
  （冊数が変われば `--check` が落ちる）
- **PNG を X のプロフィールに上げ直すのは運営者の操作**（アカウント設定の変更にあたる）

X 投稿案の「ルート 42 本」という言い回しも直した。書籍ページの「志望校別ルート N 本」は
志望レベル×型×方針で数えた本数（英語で 36）で、**志望レベルの総数（全科目で 42）とは単位が違う**。
2026-09 の手書き投稿で「42本のルート中23本」と混ざっていたため、生成側を
「志望レベル 42 段階ぶん」「ルートに N 回登場」に統一し、候補データにも注記を書いた。

### 6.8 同じ検査があったのに見逃していた理由

横スクロールは E2E に「狭い画面でも自サイト由来の横はみ出しが無い」という検査が
**既にあった**のに、7px のはみ出しを 2026-09-19 まで見逃していた。穴が 2 つ重なっていた。

1. **対象ページに参考書一覧が無かった。** 検査していたのはトップ・科目トップ・検索・記録・
   書籍 1 枚の 5 つで、カードが大量に並ぶ `/<科目>/books/` が入っていなかった
2. **Chrome で走っていなかった。** この検査は `cross-browser.spec.mjs` にあり、
   `testMatch` で Safari と Firefox だけを対象にしている。**Safari はグリッドの
   最小幅の扱いが違い、この崩れを再現しない**（実測: 修正前の CSS で Chrome 327px・
   Firefox 327px・Safari 320px）

対応として、Chrome の 4 幅（320 / 375 / 768 / 1366）で走る `flows.spec.mjs` に
「どの幅でもページ全体が横スクロールしない」を新設し、一覧・ルート・大学別を含む 11 ページを
見るようにした。`cross-browser.spec.mjs` 側も対象ページを 5 → 10 に増やし、
要素単位の検査に加えて `scrollWidth <= clientWidth` も見るようにした。

**修正前の CSS に戻すと新しい検査は落ちる**ことを確認済み（`/math/books/ で横スクロールが出る（幅 320px）`）。
検査を足しただけで満足せず、落ちることまで見ないと「捕まえられる」とは言えない。
