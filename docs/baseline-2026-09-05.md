## 7. Lighthouse ベースライン

### 測り方（以後すべてこの手順に固定する）

```bash
npm run audit:performance -- --runs=5 --path=/science/ --label=baseline-s0 --port=4181
```

`build/audit-performance.mjs` が `build/serve.mjs` でリポジトリ直下を配信し、Lighthouse を 5 回流して
各 run と中央値を `docs/perf/` へ書く。**Lighthouse か Chrome が無い環境では終了コード 2（未実施）で終わる。**

- 対象 URL: `http://127.0.0.1:4181/science/`（**localhost。本番ではない**）
- Lighthouse: 13.4.1
- Chrome: Google Chrome 152.0.7977.76
- form factor: mobile / throttling: `simulate`（Lighthouse mobile 既定）
- 実行回数: **5**、中央値を採る
- 第三者スクリプト（GA4 / AdSense）: 通常どおり読み込んだ
- commit SHA は `--commit=` で渡す（`package.json` の `audit:performance` が `git rev-parse HEAD` を渡す）。
  スクリプト自身は git を呼ばない。`test/data-integrity.test.mjs` が `build/**` からの git 呼び出しを
  禁じているため（浅いクローンで生成物が環境依存になる事故の再発防止）。

**実行回数を 3 ではなく 5 にした理由。** 3 回で測ったとき、1 run だけ LCP 23.32 秒・CLS 0 という
外れ値が出た（第三者スクリプトの読み込みが詰まり、ページが落ち着かないまま計測が終わった run）。
3 回だと外れ値が中央値の位置を動かすので、5 回に固定した。

### localhost と本番の関係についての確認

監査時点の本番実測は「mobile science Performance 47 / LCP 10.7s / CLS 0.216 / Best Practices 77」だった。
上の localhost 計測は Performance 47 / CLS 0.217 / Best Practices 77 で**一致**、LCP は中央値 12.09 秒で
本番より 1.4 秒遅い（localhost はネットワーク遅延が無い代わりに、この機械の CPU で Lighthouse の
simulate throttling が効くため）。
Performance・CLS・Best Practices が一致しているので、以後の比較は localhost で行う。
本番との突き合わせは S10 の公開確認で改めて行う。**localhost の値を本番の値として報告しない。**
