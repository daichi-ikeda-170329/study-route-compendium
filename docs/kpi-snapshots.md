# 実測スナップショット

運営ダッシュボードで読んだ数値を、**読んだ日と期間とともに**そのまま残す台帳。

## この文書の役割

| 内容 | 正本 |
|---|---|
| どの指標を見るか・どう判断するか | `kpi-plan.md` |
| 28 日集計 CSV からの機械的な取り込み | `build/import-kpi.mjs` → `kpi-baseline.json` / `kpi-baseline.md` |
| **管理画面で目視した数値の記録** | **この文書** |
| インデックス登録状況の記録 | `search-console-indexing.md` の「4. 実測の記録」 |

`kpi-baseline.json` は 28 日集計 CSV を入力にした生成物で、手で編集しない。
ダッシュボードの 7 日窓の数値をそこへ書くと、28 日の欄に 7 日の値が入って
以後の比較が成立しなくなる。**期間の違う数字を同じ欄に混ぜない。**

## 書き方の決まり

- **期間を必ず併記する。** 「716 PV」ではなく「716 PV / 7 日」と書く
- **推測で埋めない。** 読めなかったものは「未取得」と書く。0 で埋めない
- 施策を反映した日を同じ表に残す。あとで「順位変動なのか施策なのか」を切り分けるため

### この日の読み

- **急落（表示 −81%・クリック −84%）を施策の効果と混同しない。**
  上位クエリ 11 件すべてに「新規」が付いており、まだ順位が定まっていない。
  インデックス登録が始まったのは 2026-08-19（`search-console-indexing.md`）で、
  この時点でドメインは 3 週間しか経っていない。新規サイトの初期変動として扱う
- 順位は取れている（3.5〜10 位）。**負けているのではなく、狙っている語の検索数が小さい**
- 大学名のクエリが 1 件も無いのは、**大学名を持つページが 1 枚も無かった**ため。
  この日に `/univ/<slug>/` を 160 枚追加した（`README.md` の「大学別ページ」）

### 次に読むときに見るもの

1. **大学名のクエリが Search Console に現れたか。** 現れなければページが評価されていない
2. 表示回数の推移。順位は既に取れているので、伸びるとすれば表示回数
3. `/univ/` 系ページの GA4 の PV。0 のままなら内部リンクかインデックスの問題
4. Amazon / 楽天のクリック数。過去問の導線を大学別ページに新設したので、ここが動くはず

**1 週間で結論を出さない。**季節性が大きく（模試の直後・長期休み・共通テスト前後で動く）、
新規ドメインの変動も乗る。最低 28 日、できれば 2026-10-06 以降に読む。
