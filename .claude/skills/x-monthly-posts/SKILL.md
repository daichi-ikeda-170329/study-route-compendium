# X の月次投稿（月末に池田さんが依頼する）

**自動では動かさない。** 池田さんが月末に依頼したときだけ、前月までの実績を取り直し、
効いたものを増やし効かなかったものを減らして、翌月の全日分を書く。予約投稿は池田さんが貼る。

出力は `docs/x-posts/YYYY-MM.md`（翌月）。形は `docs/x-posts/2026-10.md` と同じにする。
運用の設計は `docs/x-account-plan.md`（とくに 14 節の決定 5〜7）。

## 守る条件（予約投稿だけで完結させる）

- **1 日 1 本、月の全日。** 見出しは `### M/D(曜) HH:MM — 型 — 内容`、直後に本文のコードブロックを 1 つ
- **本文の末尾に自サイトの URL を 1 本入れる**（utm 付き。6 節の `rt_a_catalog` などを型ごとに使う）
- **返信・スレッド・アンケートは使わない。** 予約できないか、できるかを確かめられていない。参加を促すときは「リプで◯◯とだけ教えてください」
- **280 以内**（全角 2・半角 1・URL は一律 23）。`build/gen-x-posts.mjs` の `weightedLen` で数える
- 数字（難易度・時間・問題数・ルートでの本数と位置）は **書籍ページの表示から写す**。ルート本数は「◯◯の志望校別ルート N 本のうち M 本の本編」の N・M を使う（全科目の段階数 42 と混ぜない）
- 試験日程など外の事実は一次情報（大学入試センターなど）で確かめ、出典をファイルの冒頭に書く
- 特定の本・講師・予備校を否定しない。「合う人／合わない人」で書く（13 節）
- 古い冊数を書かない（`npm test` の冊数検査が落ちる）

## 手順

### 1. 前月の実績を取る（推測で埋めない）

1. **X の各投稿の表示回数** — Claude in Chrome で `https://x.com/route_taizen` を開く。Chrome は株式会社O-kun のアカウントでログインしているが、表示回数は他アカウントからも見える。一覧は仮想スクロールで、長いループの JS は 45 秒で固まる。**1 回 8 スクロールまでに分け、`window.__seen` に貯めて何度か呼ぶ**:

   ```js
   window.__seen = window.__seen || new Map();
   for (let i = 0; i < 8; i++) {
     document.querySelectorAll('article').forEach(a => {
       const t = a.querySelector('time')?.getAttribute('datetime') || '';
       const txt = (a.querySelector('[data-testid="tweetText"]')?.innerText || '').slice(0, 30).replace(/\n/g, ' ');
       const g = a.querySelector('[role="group"]')?.getAttribute('aria-label') || '';
       window.__seen.set(t + txt, `${t.slice(0, 10)} | ${txt} | ${g}`);
     });
     window.scrollBy(0, 700);
     await new Promise(r => setTimeout(r, 800));
   }
   [...window.__seen.values()].sort().join('\n')
   ```

2. **フォロワー数** — プロフィールのスクリーンショットで読む
3. **返事をした件数** — `https://x.com/route_taizen/with_replies`。他の人への返事が伸ばす本命（決定 6）なので、件数を必ず数える
4. **サイトへの流入** — Vault の `00-Dashboard/ルート大全.md`（Deck が日次で書く）の「X 流入」「X 経由クリック」列。GA4 の utm_campaign 別は、Chrome で GA4 を開けたら見る。**GA4 は 2026-09-19 より前が汚染されている**ので、それをまたぐ比較はしない
5. 前月ファイルの各投稿（型・テーマ・時刻・URL の有無）と表示回数を突き合わせる

### 2. 分析する

- 型別・テーマ別に表示回数を並べる。**フォロワーが 2 桁のうちは 1 本ごとの差はほぼ偶然**なので、1 本の当たり外れで型を決めない。複数月で同じ傾向が続いたときだけ配分を変える
- 見るのは 3 つ: 表示の多かった型とテーマ ／ リプ・いいねが付いた投稿 ／ X からの流入があった日
- 返事の件数が 0 なら、投稿の配分をいじっても伸びないことを最初に書く（2026-09 がそうだった）
- 結果は新しい月のファイルの冒頭「前月の実測」「今月の方針」に数字付きで書く

### 3. 翌月の出来事を確かめる

受験生の暦に合わせると本文だけで役に立つ投稿になる。一次情報で日付を確かめてから使う。

- 共通テスト（出願・確認訂正・受験票・本番・自己採点・リサーチ）、国公立二次の出願、私大の出願締切
- 模試の返却時期、学年の節目（高 2 の冬・新高 3 の春）
- 本番までの残り日数は `node -e` で計算する

### 4. 書く

- 型の配分は分析で決める。初期値は 2026-10 の配分（A 12・B 4・C 6・D 4・E 4・質問募集 1）
- 同じ本・同じ対決の組を続けない。過去の月のファイルを `rg` で引いて重複を避ける
- A 型（図鑑カード）・E 型（データの事実）の下書きが欲しいときは `node build/gen-x-posts.mjs YYYY-MM` で出せる。ただしこれは `docs/x-posts/used.json` を書き換える。使わない本まで既出にしないよう、採用した本だけ残して used.json を直すか、出力を参考にして手で書く
- 候補データ（ルート採用の多い本・対決の候補）も同スクリプトの出力末尾にある
- 固定ポストやプロフィールに直すところがあれば、ファイルの冒頭に文面ごと書く

### 5. 検査してコミットする

```bash
node .claude/skills/x-monthly-posts/scripts/check-month.mjs YYYY-MM   # 全日・280 以内・URL 実在・返信/アンケート混入なし
npm run check:data && npm test && npm run check:site && npm run check:counts
```

通ったらコミットして push する。Vault の `00-Dashboard/確認事項.md`（AI 節）に「翌月分を予約投稿する」を 1 行で置き、最初の投稿の日時を書く。

### 6. 最終報告に書くこと

前月の実測（フォロワー・表示回数の上位と下位・返事の件数・流入）、そこから変えたこと、確かめられなかったこと、池田さんの作業（予約・プロフィール修正・返事）。
